# The contract the API publishes

These files are what the admin, the mobile app and the agent are entitled to
rely on. None of them is written by hand: the `Contract` PHPUnit suite
(`api/tests/Contract/`) generates them from the running application, and the
clients' own test suites read them back.

| File | Generated by | Read by |
|---|---|---|
| `openapi.json` | `OpenApiContractTest` | mobile `QueryParameterContractTest`, admin `queryParameters.contract.test.ts` — it is what they check a sent parameter against |
| `mcp-tools.json` | `McpToolsContractTest` | nothing yet — it is the reviewed diff |
| `mercure-topics.json` | `MercureTopicContractTest` | mobile `MercureTopicsContractTest`, admin `useMercure.contract.test.ts` |
| `query-parameters.json` | `QueryParameterContractTest` | the same tests, which keep the list complete |
| `responses/*.json` | `RecordedResponseContractTest` | mobile `DtoContractTest` |

The agent publishes its own topics (`/chat/{userId}`, …) outside `/users/`, so
they are not in `mercure-topics.json`. They have the same kind of file,
`agent/contract/mercure-topics.json`, written by the agent's
`tests/test_mercure_topics_contract.py` (`UPDATE_CONTRACT=1 task wt:test:agent
-- tests/test_mercure_topics_contract.py`) and read by the same mobile and
admin tests.

## Why files, and not assertions in each suite

Because the failures these catch are silent. A Mercure topic the client
subscribes to and nobody publishes connects and delivers nothing. A DTO field
named `isCushion` where the API sends `cushion` deserialises to the declared
default, and the screen shows a value the user never chose. A query parameter
API Platform does not declare is dropped, and the list comes back unfiltered.
No exception, no log, no failing test — until somebody notices the app is
wrong.

Comparing two independent statements of the same contract is the cheapest way
to catch that, and a committed file is how the two sides compare without a
running stack.

## Changing one

Nothing here forbids a breaking change. It forces it into the diff:

```sh
task wt:test:api -- --testsuite Contract              # see what moved, and why it matters
UPDATE_CONTRACT=1 task wt:test:api -- --testsuite Contract
```

Then read the diff before committing, and check the client that reads the file
you changed. `mercure-topics.json` and `responses/` have readers in
`mobile/app/src/test/` and `admin/src/`; those suites run in CI on a change to
this directory.

## Why it lives under `api/`

`task wt:test:api` mounts `api/` alone into its container. A directory at the
repository root would be invisible to the suite that maintains it.
